1. RESUMEN GENERAL
================================================================================

ChemiTech es una aplicación educativa de química en Unity (móvil + PC) donde el
usuario construye moléculas colocando átomos en un espacio 3D. La app NO decide
los enlaces: envía la configuración de átomos a un backend que resuelve la
estructura química real y devuelve los enlaces, la fórmula y las propiedades.
Los hallazgos se registran en un "Diario" de moléculas descubiertas.

Conceptos centrales:
  - UNIVERSO: una partida/espacio de trabajo guardado, con nombre, icono, color,
    tiempo jugado y los átomos/enlaces que el usuario colocó.
  - ÁTOMO: elemento del catálogo (24 disponibles) que se coloca en el mundo 3D.
  - DETECCIÓN: proceso automático que agrupa átomos por cercanía y consulta al
    backend para resolver qué molécula forman.
  - DIARIO: catálogo de moléculas que el usuario ha descubierto.

Modos de uso:
  - INVITADO (guest): juega sin cuenta. No guarda progreso en servidor, no tiene
    diario persistente en la nube, y el tutorial se le muestra siempre.
  - LOGUEADO: tiene cuenta, universos, diario, estadísticas y perfil.

2. STACK TÉCNICO
================================================================================

  - Motor:            Unity (proyecto 3D con UI en Canvas)
  - Lenguaje:         C#
  - UI:               Unity UI (uGUI) + TextMeshPro (TMP)
  - Fuente principal: Fredoka-Medium SDF
  - Red:              UnityWebRequest (coroutines), JSON con JsonUtility
  - Backend local:    http://127.0.0.1:8000/api  (FastAPI/uvicorn)
  - Persistencia:     PlayerPrefs + archivos JSON locales (DeviceStorage)
  - Plataformas:      PC (editor/standalone) y Android (probado en móvil)

RESTRICCIÓN IMPORTANTE DE UI (afecta cualquier feature nueva):
  La fuente Fredoka NO tiene fallback ni hay sprite asset de emojis en el
  proyecto (m_FallbackFontAssetTable vacío, defaultSpriteAsset es una
  referencia rota). Por lo tanto:
    - NO usar emojis ni glifos especiales (⟳ ✓ ✕ → ⬆ 👆 🔗 …) dentro de texto TMP:
      se renderizan en blanco.
    - Los iconos deben ser Image + sprite real.
    - Los subíndices químicos van en ASCII ("H2O", no "H₂O"). Existe el helper
      AtomCatalog.NormalizeFormula() que convierte subíndices Unicode a ASCII.
    - Símbolos ASCII sí funcionan (el HUD usa "II" para pausa y "X" para cerrar).

    Valida con POST /authentication/validate/username
  Paso 4 — Cuenta creada:
    Llama POST /authentication/account y muestra confirmación.

5.4 RECUPERACIÓN DE CONTRASEÑA (4 pasos)
--------------------------------------------------------------------------------
Managers: ForgotPassword/ForgotPassword{Email,Code,Reset,Success}Manager.cs

  Paso 1 — Correo:   POST /authentication/password/reset/request
  Paso 2 — Código:   6 casillas alfanuméricas con auto-avance, retroceso con
                     backspace y pegado distribuido. Verifica con
                     POST /authentication/password/reset/verify (no consume el
                     código). Botón "Reenviar" con cooldown de 60 segundos.
  Paso 3 — Nueva contraseña: mismo validador de fuerza que el registro.
                     POST /authentication/password/reset
  Paso 4 — Éxito:    Limpia PasswordResetData y SessionData (el backend revoca
                     todas las sesiones) y vuelve a LoginScene.

7. SISTEMA DE DETECCIÓN DE MOLÉCULAS  ★ NÚCLEO EDUCATIVO
================================================================================

Manager: Game/BondManager.cs

PRINCIPIO CLAVE: la app NO decide los enlaces. Solo agrupa átomos por cercanía
para separar candidatos y envía cada grupo al backend con bonds vacío. El
backend resuelve la química real y devuelve los enlaces con su orden
(simple/doble/triple), que la app dibuja.

7.1 Ciclo de detección
  1. Cada frame se calcula un "hash" de la estructura (posiciones + elementos)
  2. Si cambió, se reinicia un debounce (detectDelay ≈ 0.45s)
  3. Cuando la estructura se estabiliza, se agrupan los átomos por distancia
     (clusterDistance ≈ 2.0) → cada grupo es un candidato
  4. Por cada candidato se hace POST /detection/molecule con:
       { atoms: [{id, element, x, y, z}], bonds: [] }
     (ids locales 0..n-1, mapeados a los Atom3D reales)
  5. La respuesta trae isValid, molecule{...} con bonds, fórmula y propiedades
  6. Se dibujan los enlaces devueltos y se muestra el banner si CAMBIARON

7.2 Dibujado de enlaces
  - Cada enlace se dibuja como N cilindros paralelos según su orden
    (1 = simple, 2 = doble, 3 = triple); separación ≈ 0.20
  - Enlaces BICOLOR: cada mitad lleva el color de su átomo, como en un visor
    molecular estándar
  - Se reutiliza un material por elemento para no disparar el número de
    materiales en moléculas grandes

7.3 Banner y anti-repetición
  - Antes de cada detección se guarda una "firma" de los enlaces ya dibujados
  - El banner "¡Molécula formada!" solo aparece si la firma CAMBIÓ. Reconfirmar
    una molécula existente (p. ej. al colocar un átomo suelto aparte, o al
    recargar el universo) NO vuelve a mostrar el banner.

7.4 Modo offline / servicio caído
  - Error de red, timeout o 5xx → se marca el servicio como NO DISPONIBLE
  - Cualquier respuesta del servidor (válida o no) → se marca DISPONIBLE
  - Mientras está caído, reintenta automáticamente cada ~5s (offlineRetryInterval)
    sin requerir interacción del usuario
  - El aviso "detección no disponible" solo se muestra si además HAY una
    estructura que detectar, y se auto-oculta tras ~3s (offlineIndicatorDuration)
  - Colocar, mover y borrar átomos SIEMPRE funciona aunque el servicio esté caído
  - Las peticiones tienen timeout de 10s para evitar conexiones colgadas
    (especialmente importante en móvil)

7.5 Comportamiento conocido a revisar  [PENDIENTE]
  - Con CO2 el backend devuelve correctamente 3 enlaces.
  - Con H2O el backend devuelve isValid=true y fórmula "H2O", pero con
    bonds: [] (vacío), por lo que no se dibuja ningún enlace. El SMILES que
    devuelve es "[H+].[OH-]" (especies iónicas separadas). Parece un problema
    del BACKEND al generar enlaces en estructuras iónicas, no del cliente.
  - Pruebas sugeridas para acotar: O2, N2, Cl2, H2, CO, NH3, CH4, H2S, NaCl.

9. AUTENTICACIÓN
================================================================================

Modelo: access token (Bearer, ~30 min) + refresh token (deslizante, un solo uso).

9.1 Envío
  Todos los endpoints protegidos envían:  Authorization: Bearer <accessToken>
  (Ya NO se usan los antiguos headers public_id / user_public_id.)

9.2 Refresh automático con reintento
  - SendAuthed() envuelve toda petición autenticada.
  - Ante 401 ERR_TOKEN_EXPIRED: llama a POST /session/refresh, actualiza los
    tokens y REINTENTA la petición una vez, de forma transparente.
  - El refresh es SINGLE-FLIGHT: si varias peticiones caducan a la vez, solo se
    hace un refresh y las demás esperan su resultado (el refresh token es de un
    solo uso).

9.3 Sesión muerta
  - Ante ERR_TOKEN_INVALID / ERR_TOKEN_MISSING, o si el refresh falla:
    se limpia SessionData y se navega a LoginScene (una sola vez, con guarda).
  - 403 ERR_NOT_RESOURCE_OWNER solo se registra en log (indica bug de cliente).

9.4 Invitado vs logueado en detección
  - INVITADO: sin token y sin userPublicId en el cuerpo
  - LOGUEADO: con Bearer y con userPublicId (que debe coincidir con el del token)
  - Los errores de conexión (código 0 o 5xx) los trata BondManager como "offline"

9.5 Persistencia de sesión
  Services/SessionData.cs guarda en PlayerPrefs:
    chemitech_session_userid / username / email / access / refresh /
    tokentype / expires
  IsLoggedIn = hay accessToken no vacío.

13.1 Builders de editor ADITIVOS
  Las pantallas se construyen con herramientas de editor bajo el menú
  "ChemiTech/...". Regla: NUNCA usar builders destructivos que recreen la
  escena desde cero. Los builders deben ser idempotentes (buscar-o-crear).

  Escenas AJUSTADAS A MANO — no reconstruir destructivamente:
    - ZonaJuegoScene (su builder original BORRA el HUD)
    - DiaryScene

  Herramientas aditivas existentes para ZonaJuegoScene:
    ChemiTech → Add → Tutorial (ZonaJuego) ...... TutorialTool.cs
    ChemiTech → Add → Detection Indicator ....... DetectionIndicatorTool.cs
    ChemiTech → Add → Discovery Modal ........... DiscoveryModalTool.cs
    ChemiTech → Fix → Icon Glyphs (ZonaJuego) ... IconGlyphFixTool.cs

  Otros builders: LoginSceneBuilder, MainMenuBuilder, RegisterEmailBuilder,
  RegisterPasswordBuilder, RegisterUsernameBuilder, CuentaCreadaBuilder,
  ForgotPassword{Email,Code,Reset,Success}Builder (+ ForgotPasswordUI compartido),
  MisUniversosBuilder, CrearUniversoBuilder, EditarUniversoBuilder,
  DiaryBuilder, MoleculeDetailBuilder, PerfilBuilder, SettingsBuilder,
  GuestPromptBuilder.

13.2 Patrón de pantalla
  Cada pantalla = Builder (editor, crea y cablea la UI) + Manager (runtime,
  lógica) + Scene. El cableado de referencias se hace con SerializedObject
  desde el builder, no arrastrando a mano en el inspector.

13.3 Texto e iconos
  Ver la restricción de fuente en §2. Resumen: iconos = Image + sprite;
  nada de emojis ni glifos especiales en TMP; subíndices en ASCII.
